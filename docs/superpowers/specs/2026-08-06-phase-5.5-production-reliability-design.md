## 1. Intent

Phase 5 closed the production loop (try-first → compare → drill → shadow → spaced recall). That helps practice, but it does not yet **prove** week-over-week improvement. The founder’s need:

> Feel the intermediate → fluency needle move — with a trustworthy signal based on **production reliability**, not rote deck size or gamified streaks.

Phase 5.5 ships a **thin progress layer**: log drill reviews, compute a rolling reliability %, show it on `/practice`. Soft grades now; stricter attempt-before-reveal scoring later (Phase 7). Cloud sync waits for Phase 6.

### Decisions locked in brainstorming

| Decision | Choice |
|---|---|
| Sequencing | Progress dashboard first, then richer retention drills |
| Hero metric | Production reliability (not quality or coverage) |
| Success definition | Soft now (Good/Easy self-grades) → strict later (attempt before reveal) |
| Timing | Thin Phase 5.5 now; Phase 6 OAuth/sync next; Phase 7 retention + stricter scoring |
| Approach | Grade-log + rolling reliability (not snapshot-only, not full coach) |

## 3. Metric definition

### Production reliability

A review is **reliable** (soft mode) when `grade` is `good` or `easy`.

\[
\text{reliability}_{W} = \frac{\#(good + easy)\ \text{in window } W}{\#\ \text{all reviews in window } W}
\]

| Window | Role |
|---|---|
| **7 days** | Primary hero number |
| **30 days** | Secondary calmer % |
| **ISO weeks (last 8)** | Sparkline series (reliability % per week) |

### Building-signal threshold

If fewer than **5** reviews fall in the primary (7-day) window, do **not** emphasize a loud percentage. Show “Building signal…” (or equivalent) with review count so early noise does not demoralize.

### Empty state

No reviews ever: “Practice a few due phrases to unlock your needle.” No fake 0%.

### Soft → strict path (documented contract)

Phase 5.5 events use `mode: 'self_grade'`. Phase 7 may introduce `mode: 'attempt_match'` (or equivalent) and redefine success as “produced without peeking.” The needle formula stays **success / reviewed**; only the success predicate changes. Do not invent a second progress model.

## 4. Data model

### Shared type

```ts
type ReviewGrade = 'again' | 'hard' | 'good' | 'easy' // existing

interface ReviewEvent {
  id: string
  phraseId: string
  grade: ReviewGrade
  reviewedAt: string // ISO
  mode: 'self_grade' // Phase 5.5; extend later
}
```

Add `ReviewEvent` to `packages/shared` alongside existing practice types.

### Storage

| Store | Key | Notes |
|---|---|---|
| Review events | `myl-review-events` | Append-only log; cap **1000** newest events |
| Phrasebook / SRS | `myl-phrasebook` | Unchanged SM-2-lite `practiceStats` |

### Write path

On practice drill grade:

1. Existing `recordReview(phraseId, grade)` updates `practiceStats` / schedule  
2. Also append a `ReviewEvent` with `mode: 'self_grade'` and `reviewedAt = now`

SRS scheduling and the event log stay separate: scheduling answers “when next?”; the log answers “how reliable over time?”

### Phase 6 sync hook

When OAuth + Postgres land, migrate `ReviewEvent[]` with phrasebook/SRS. Same shape — no parallel progress schema.

## 5. UI & placement

### Primary: `/practice` progress strip

Above mode controls / drill queue:

- Large **7-day reliability %** (or “Building signal…” if &lt; 5 reviews in window)
- Subline: “X of Y reviews reliable · last 7 days”
- Quiet **30-day** secondary %
- Small **8-week** sparkline
- Label: **Based on self-grades**

Read-only in 5.5 — no metric settings UI.

### Layout principles

- One composition: progress strip → drill controls → card  
- Not a dashboard of cards, streaks, or secondary marketing stats  
- After each grade, needle refreshes in-session so the learner feels “that one counted”

### Secondary surfaces

- Optional tiny header % is **out of scope** for 5.5  
- No new top-level “Progress” route in 5.5

## 8. Success criteria

- [ ] Each drill self-grade appends a `ReviewEvent` without breaking SRS scheduling
- [ ] `/practice` shows 7-day reliability (or building-signal / empty state) with soft-mode label
- [ ] 30-day % and 8-week sparkline render from the same log
- [ ] Needle updates after grading in the same session
- [ ] Event log capped; `localStorage` key stable (`myl-review-events`)
- [ ] No regression to Phase 5 try-first / drill / shadowing / SRS flows
- [ ] Spec documents Phase 7 stricter scoring + retention drills without implementing them

## 9. Phase 7 foreshadow (not in this ship)

- Optional secondary: production quality vs model/native alternative — never replaces reliability as hero  
- May add a dedicated progress view once the signal is trusted
